Subsystem 01

Spec Engine · 需求澄清引擎

五阶段确定性流水线：在执行任务前自动判断澄清必要性、探索代码库上下文、起草结构化规格、 识别关键决策点并等待用户确认，最终合成增强提示词。支持模型分层路由与失败回退。

Classifier · 分类器
判断用户输入是否需要走 Spec 澄清流程。使用 small LLM 低成本快速决策： 当置信度 confidence ≥ 0.6 时直接跳过澄清进入执行。 回退策略支持三档：primary（由主模型决策）、strict（一律走澄清）、 skip（一律跳过）。失败时默认 fail-closed 走澄清路径。
Explorer · 代码探索器
调用主模型（primary LLM）配合 只读工具（文件读取、grep、glob 等）探索代码库， 收集入口点、已存模式、约束条件。由 maxExplorationRounds 控制最大探索轮数， 产出结构化上下文：entryPoints（入口文件）、patterns（现有实现模式）、 constraints（架构红线与约定）。探索结果写入 SpecDocument.understanding。
Drafter · 规格起草器
使用 3B–7B LLM（强推理模型）输出结构化 SpecDraft，包含： topic（任务主题）、understanding（需求理解）、 taskBreakdown（任务分解树 SpecTaskNode[]）、 keyDecisions（关键决策点）。此阶段是流水线核心，输出直接决定后续执行质量。
Decision Detector · 决策检测器
使用 small LLM 扫描 SpecDraft 中的关键决策点，按严重程度分级： critical（阻塞性，架构/技术选型级）、major（重要，API/接口级）、 minor（次要，实现细节级）。其中 critical + major 标记为 blocking，必须通过交互确认面板获得用户裁决后才能继续； minor 决策可自动选择默认值。
Enhancer · 提示词增强器
使用 3B–7B LLM 将已确认的 SpecDocument 合成为 enhancedPrompt—— 一份包含完整上下文、任务分解、决策记录与验收标准的高质量系统提示词，注入后续 Agent 执行循环。 当模型调用失败时，fallbackEnhance() 提供确定性字符串拼接兜底，保证流水线不中断。 最终产物持久化到 SpecStore，状态置为 completed。
fallback chains:   classifier-fail → strict (always-clarify)  |  explorer-fail → skip with empty context  |  drafter-fail → retry × 1 → minimal spec  |  enhancer-fail → fallbackEnhance() (deterministic)

Event System · 事件流

Spec Engine 通过类型化事件与外部系统（CLI/TUI/SDK）通信，每个事件携带精确 payload，支持进度追踪与 UI 绑定。

Event When · 触发时机 Fields · Payload
spec_start Classifier 判定需要澄清，流水线启动时 input: string, trigger: SpecTrigger
spec_stage 每个阶段完成时（含回退） stage: StageName, model: string, durationMs: number, fellBack: boolean
spec_draft_ready Drafter 成功产出 SpecDraft specId: string, topic: string, understanding: SpecUnderstanding
spec_confirmation_required 检测到 blocking 决策，需要用户交互 specId: string, decisions: SpecDecision[]
spec_confirmed 用户完成所有决策确认 specId: string, decisions: ResolvedDecision[]
spec_completed Enhancer 完成并持久化 specId: string, enhancedPrompt: string
spec_skipped Classifier 判定跳过或用户取消 reason: 'confidence' | 'user-decline' | 'policy'

Audit Path · 审计路径
Focus Kernel —— 独立的确定性审计执行路径

Focus Kernel 是与 Spec Engine（会话型路径）严格隔离的审计型执行路径， 位于 packages/harness-core。它以确定性状态机驱动，拥有 16 个状态（CREATED → PREFLIGHT → PLANNING → ... → ACCEPTED / REJECTED / CANCELLED / FAILED / EXPIRED）， 通过四个严格类型化的 Port 与外界交互，实现 Decision/Effect 分离与可重放性。

该路径不依赖会话循环、不直接调用模型、不执行副作用；所有 Effect 必须经过 Grant 授权与 Receipt 回收， 适用于企业级审计、合规与可验证执行场景。Spec Engine 的最终 enhancedPrompt 可作为 Kernel 的 Intent 输入，但两者状态机不共享。

16 states 4 ports: Decision / Effect / Fact / Verify Intent → Grant → Receipt model Deterministic & replayable packages/harness-core
Subsystem 02

TUI · 全屏终端界面

基于终端状态机的全屏交互界面，支持多布局、主题/皮肤、伙伴成长、命令面板、Vim 模式与 Spec 进度可视化。 所有渲染走 ANSI 转义序列流水线，纯 Node.js 运行，无 GUI 依赖。

Subsystem 03

Integration · 集成桥接

Agent Runtime 发出的类型化事件如何穿过 CLI 组合根的桥接层，驱动 TUI 状态更新并最终渲染到终端。

Event Flow · 事件流转路径

从 Agent Runtime 发出 spec_* 事件到终端像素更新的完整数据流。

AgentEvent spec_start · spec_stage · spec_draft_ready · spec_confirmation_required · spec_completed · spec_skipped
↓ event bus (typed emitter)
renderEvent() apps/cli/src/tui.ts
↓ event translation / dispatch
TUI State setSpecProgress() · updateSpecStage() · setSpecConfirmation() · setSpecDraft() · completeSpec()
↓ reactive state change → invalidation
Renderer ANSI escape sequences → stdout → terminal

Spec Confirmation Flow · 决策确认交互

当 Decision Detector 发现 blocking decisions 时，TUI 弹出覆盖层拦截输入焦点，流水线暂停等待用户裁决。

1
spec_confirmation_required 事件到达
事件携带 specId 与 SpecDecision[] 数组，每个决策含 question、options、 severity、recommendedIndex。CLI 层调用 setSpecConfirmation(decisions) 写入 TUI 状态。
2
TUI 渲染确认覆盖层
Renderer 在转录区上方叠加半透明决策面板：显示问题文本、选项列表（推荐选项高亮标记）、 决策序号（[1/3]）与严重程度色标。转录区暂停滚动，输入框临时替换为决策导航提示。
3
用户导航与裁决
↑/↓ 或 Tab 在选项间移动，Enter 确认当前选项进入下一决策， Esc 整体拒绝（触发 spec_skipped(reason: 'user-decline')）。 每个决策确认后立即更新状态，面板推进到下一项。
4
回调触发
全部决策完成后，onSpecConfirm(decisions) 回调触发；若用户按 Esc 则触发 onSpecDecline()。回调在 CLI 组合根中绑定到 Spec Engine 的 resolveDecisions() 方法。
5
流水线恢复
specEngine.resolveDecisions(resolved) 将裁决写回 SpecDocument.keyDecisions， 流水线进入 Enhancer 阶段，最终产出 enhancedPrompt 并发出 spec_completed， TUI 关闭覆盖层，Agent 执行循环开始。
Changelog

v0.4-beta.2 Optimizations Summary · 优化汇总

v0.4-beta.2 迭代中完成的关键优化项汇总，覆盖 Spec 引擎、TUI 交互、排版动画与健壮性修复。 本轮共修复 6 项高优 / UX / 代码质量问题，剩余 1 项（终端色深自动探测）待后续版本处理。

Spec Engine Improvements · 规格引擎改进

提升规格草案的可审查性与历史可追溯性，让用户在 Agent 执行前能完整理解并决策。

Spec Draft Preview
spec_draft_ready event · tui.ts
spec_draft_ready 事件现在携带完整的 taskBreakdown 数组。TUI 预览面板渲染 understanding（需求理解）、taskBreakdown（任务分解）与 decisions（关键决策）三部分，采用粗体标题 + 暗色元数据的排版层次，用户可在确认前逐项审查。
Spec History Browser
specHistoryView · renderSpecHistory() · Alt+H
新增 specHistoryView 状态追踪已完成规格（specId、topic、completedAt、totalDuration、stages、status）。 renderSpecHistory() 覆盖层提供可滚动历史列表：状态图标（● 完成 / ○ 进行中）、 相对时间戳、阶段分解、选择高亮。Alt+H 打开，Up/Down/j/k 导航，Esc 关闭。

TUI Interaction Improvements · 终端交互改进

增强 Split 布局下的键盘导航与面板操作能力，让多面板工作流可完全通过键盘驱动。

Active Pane Focus Cycling
activePane · cycleSidebarFocus() · Alt+]
新增 activePane 状态（"input" | "todo" | "spec" | "context"）， cycleSidebarFocus() 在侧栏面板间循环切换焦点。聚焦面板边框以品牌橙渲染， 非聚焦面板边框以暗色渲染，提供清晰的视觉焦点反馈。
Pane Action Dispatch
performSidebarAction() · Alt+Enter
performSidebarAction() 对当前聚焦面板执行上下文操作：Todo 面板切换复选框、 Spec 面板展开/折叠、Context 面板刷新等。Alt+Enter 触发， 让侧栏面板无需鼠标即可完成全部交互。

Typography & Animation · 排版与动画

实现完整的 ANSI 样式消费与微动画系统，让终端输出具备丰富的视觉层次与流畅的状态反馈。

Rich Typography Rendering
bold() · italic() · faintLocal() · renderer.ts
Renderer 现消费 spec-progress 与 markdown 渲染管线中的 bold / italic / dim / underline ANSI 样式。 新增 bold()、italic()、faintLocal() 辅助函数。 标题以粗体渲染，元数据以暗色渲染，强调以斜体渲染，重要文本以下划线渲染。
Toast Notification System
toast · fade animations · renderer.ts
实现 toast 通知系统，支持淡入淡出动画（右上角定位，3 秒后自动消失）， 提供 success / warning / error / info 四种语义变体，与品牌色系统一致。 操作反馈不再依赖硬切文本。
Shimmer Loading Effect
shimmer · stage transitions · renderer.ts
新增 shimmer 微光加载效果，用于 Spec 阶段等待、工具执行中等异步状态。 阶段过渡（stage transitions）现具有微妙的视觉反馈，状态切换平滑自然， 消除了此前的硬切跳变感。

Robustness Fixes · 健壮性修复

修复取消信号传播缺陷与持久化防抖问题，提升高并发交互下的响应性与资源效率。

AbortSignal Propagation
controller.signal · exploreCodebase() · tool.execute()
controller.signal 现沿 exploreCodebase() 传递到所有工具执行路径：read / write / edit / ls / runProcess / grepRecursive / listFiles。工具实现接受并遵守 AbortSignal，超时或用户中断时慢工具可被及时终止。
Companion Persistence Debounce
persistCompanion() · 500ms debounce
为 persistCompanion() 添加 500ms 防抖，快速连续的 agent_end 事件合并为单次磁盘写入，显著降低高频交互下的 IO 压力， 避免 Companion 状态在快速操作中产生不必要的磁盘抖动。
Command Palette Wiring
setPaletteCallback() · 16 commands · tui.ts
通过 tui.setPaletteCallback() 接入全部 16 个命令的处理逻辑： 布局切换（classic/split/focus/wide/cycle）、Vim 模式切换、搜索、模型选择、Todo 面板、 Spec 拒绝、会话新建/分叉、推理展开、记录清空、Spec/Context 侧栏切换。
Sidebar Pane Toggle
toggleSidebarPane() · pane:toggle_spec/context
新增 toggleSidebarPane(paneId) 方法与命令面板命令， 可单独控制 Spec / Context 面板显隐；toggleTodoPanel 现同步 layout pane 状态，setLayoutMode 切换时同步 todoPanel.visible。
Remaining: 终端色深自动探测（根据 TERM / COLORTERM 自动降级 truecolor → 256 → 16 色）尚未实现， 将在后续版本中处理。当前默认 truecolor 输出，在绝大多数现代终端下工作正常。
